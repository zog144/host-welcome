# Local graphical transition — acceptance gate proposal (2026-10-20)

**No production activation authorized.** `graphical_transition.evaluate_graphical_transition()` is a **pure source-test decision**, not a session manager, kiosk execution engine or privileged local seat API. No current code path calls it to take a TTY, start greetd, change login state, launch Firefox, or touch controller/systemd. It always retains the existing console/getty, including a positive synthetic result. Future consumers must provide independently authenticated inputs before a positive result can be meaningful.

The positive condition requires: image-build's same host-install selection revision for all required selected immutable application software; `view-published-compatible` for Xorg, i3, greetd and the chosen browser, including independently checked rootfs compatibility; controller runtime observations bound to the exact selected view IDs and accepted boot; no missing/non-atomic controller pages; a separate approved **physical local-seat** observation with PAM grant, logind session ownership, display readiness, browser page/render readiness, current boot/freshness, and selection binding. Remote TurboVNC workspaces are **not** interchangeable with physical seats. The initial browser is Firefox ESR; Firefox and Chromium are supported alternatives only when their selected views/runtime evidence exist.

`LocalSeatEvidence` is deliberately a local Python test **placeholder**, not a producer-authenticated schema. box-control/root-control/host-install must agree on a versioned seat observation, selected privileged greetd role and root-owned binding before any trusted adapter can construct it. The current controller `local-session` contract is inert and cannot establish physical-seat readiness. image-build's publication receipt does **not** attest a running browser or authorize PAM/login. Do not turn a passing model-level test into host runtime activation.

Fault tests require console fallback for: no network, unavailable controller/observer, missing X11/browser view, partial publication, job/build uncertainty after reboot, disabled PAM grant, crashed display/browser, changed view, wrong boot and remote VNC. Actual rollback behavior and automatic display handoff require independent disposable-host Work acceptance.
