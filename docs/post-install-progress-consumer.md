# Post-install progress producer adoption (2026-10-20)

The pinned image-build source at `7b653e8be3f89730a52688d71df28513456f9cf3` implements `image-build-post-install-progress-v2`, projection `snapshot()` and a read-only AF_UNIX producer broker. Host-install owns the immutable selection receipt; image-build reports request revision, pipeline/attempt/stage/command identities and separately verified artifact/view/rootfs compatibility publication. Controller build-job status is separate and must not be treated as publication. This consumer validates a bounded single page with strict schema/identity/state/receipt-shape checks and can correlate observable job IDs without inventing completion or losing independently verified publication history.

**Producer source readiness is not deployment acceptance.** The image-build broker has no approved host-install socket/UID/systemd deployment profile yet. `host-welcome` must not connect to a user-supplied state directory, raw producer path or an unreviewed listener; no live image progress is exposed by the CLI until a separate root-owned fixed socket/policy, distinct image-build producer UID, source-byte attestation, peer credentials, and native acceptance have been reviewed. This module is pure validation/join and cannot grant trust to `--input` fixtures. In the meantime `host-welcome-progress --live` continues to show publication unobserved.

The `selection_revision` attests the image-build owner receipt derived from host-install intent. Independent host-install selected application/rootfs binding must be cross-checked when that producer exposes it; until then local graphical transition cannot be triggered. One response page is not atomic with controller pages, and `commands_truncated` and `page.has_more` are explicitly incomplete. No synthesized percent or ETA is allowed.

### Durable pipeline status versus live execution

A producer pipeline recorded as `running` does not prove a process is currently executing. The console keeps the `building` phase visible but reports the effective state as `uncertain` when independent live execution evidence is unavailable, including across reboot, network loss or pruned controller pages. The underlying immutable attempt and command identities are retained; no retry is initiated by the console.

### Authenticated response identity

The consumer pins image-build runtime `7b653e8be3f89730a52688d71df28513456f9cf3` and contract `image-build-post-install-progress-linux-credentials-v1`. The systemd-owned listener `SO_PEERCRED` may be root/PID 1; only Linux `SCM_CREDENTIALS` sent with the **first reply byte** establishes the non-root responder identity. The fixed `snapshot` request has no credentials or private state selection. Credential rejection occurs before decoding the JSON response, after which the strict v2 source, boot, freshness, publication and pagination validators apply. The separate host-install deployed policy and installed wheel attestation must agree with the new pin; no production GO until native acceptance.
